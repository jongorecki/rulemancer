# Cross-judge neutral read: does the opus-vs-gpt5mini ranking hold under a third judge family?

2026-07-27. OpenRouter only, zero Anthropic spend.

## Method

Two models answered byte-identical prompts over the same 1,409-question corpus:

- `claude-opus-5` low → `evals/answers/headline_full.json` ("opus5-low")
- `openai/gpt-5-mini` → `evals/answers/gpt5mini_fair_merged.json` ("gpt5mini")

Both are normally scored by `openai/gpt-5-mini` (`judge_rulesguru.JUDGE_SLUG`), which
shares a model family with one of the two contestants — a same-family bias risk on
that arm. `evals/judge_rulesguru.py` and `evals/judge_norules_control.py` gained a
`--judge <openrouter-slug>` flag (default unchanged: `openai/gpt-5-mini`, so every
existing call site and script is unaffected) so any OpenRouter model can grade
instead. The chosen judge model and a sha256 of the exact system prompt are written
into every output file's `summary.judge_model` / `summary.judge_prompt_sha256`
fields — five existing verdict files in this repo are flagged `[crit]` on the
dashboard for omitting exactly that, so the new flag was built to close that gap,
not repeat it.

`evals/_crossjudge_subset.json` holds 150 ids, level-stratified from the 1,409-row
corpus (seed 20260727: 22×L0, 60×L1, 43×L2, 17×L3, 8×Corner Case). Both models'
answers were filtered to these 150 ids
(`evals/_crossjudge_answers_opus_150.json`, `evals/_crossjudge_answers_gpt5mini_150.json`)
and judged by two OpenRouter models outside both the Claude and the OpenAI
families:

- `deepseek/deepseek-v3.2`
- `google/gemini-2.5-flash-lite`

Every row got 3 independent judge calls (`--votes 3`); the majority verdict is the
per-row score, with every vote retained for the split-rate figures below.

Output files: `evals/verdicts_crossjudge_<judgeslug>_<arm>_votes3.json` (4 files,
150 rows each — deepseek×opus, deepseek×gpt5mini, gemini×opus, gemini×gpt5mini).

**Cost control.** A 20-row stratified pilot (`evals/_crossjudge_pilot20_opus.json`,
one arm, both judges, 3 votes = 120 calls) measured actual token usage per call
(the judge helper itself does not record usage) and priced it against OpenRouter's
published per-token rates (fetched live: deepseek-v3.2 $0.2072/$0.3108 per 1M
in/out tokens; gemini-2.5-flash-lite $0.10/$0.40 per 1M in/out tokens). Projected
cost for the full 150×2×2×3 = 1,800-call design: **$0.25**, well under the $8 cap,
so the design ran as specified — no trimming was needed.

## ⚠️ Unvalidated-judge caveat — read before trusting these numbers

`evals/judge_bakeoff.py` lists both `deepseek/deepseek-v3.2` and
`google/gemini-2.5-flash-lite` as candidate judges, and verdict files from earlier
runs using them exist on disk (e.g. `evals/verdicts_deepseek-v3-2.json`,
`evals/verdicts_gemini-flash-lite.auto.json`) — but neither was ever characterised
against a trusted reference (the way gpt-5-mini was, at ≥95% agreement with a
sonnet-5 judge, before being adopted as `JUDGE_SLUG`). The project's dashboard
skips these files ("bare array, no summary") and no agreement-with-a-trusted-judge
figure is recorded anywhere for either model.

**That means this run answers "does the ranking flip when the judge's model family
changes?" — it does NOT answer "which model is actually better," and it should
never be quoted as if gpt-5-mini's 85.88% headline can be replaced by either of
these numbers.** Treat both deepseek and gemini here as an independent second (and
third) opinion on *direction*, not as calibrated accuracy instruments.

## Per-judge results (150-row stratified subset)

| Judge | Arm | Accuracy | 95% CI (Wilson) | Split rate (2-1 votes) |
|---|---|---|---|---|
| `deepseek/deepseek-v3.2` | opus5-low | 131/150 = **87.3%** | [81.1%, 91.7%] | 1/300 combined = 0.3% |
| `deepseek/deepseek-v3.2` | gpt5mini | 105/150 = **70.0%** | [62.2%, 76.8%] | (same row) |
| `google/gemini-2.5-flash-lite` | opus5-low | 113/150 = **75.3%** | [67.9%, 81.5%] | 0/300 combined = 0.0% |
| `google/gemini-2.5-flash-lite` | gpt5mini | 89/150 = **59.3%** | [51.3%, 66.9%] | (same row) |
| `openai/gpt-5-mini` (own family, restricted to same 150 ids) | opus5-low | 128/150 = **85.3%** | [78.8%, 90.1%] | 3/150 = 2.0% |
| `openai/gpt-5-mini` (own family, restricted to same 150 ids) | gpt5mini | **not available** — `evals/verdicts_gpt5mini_fair_votes3.json` was still being generated by a separate full-corpus run when this analysis was written; not regenerated here to stay inside the OpenRouter budget and avoid duplicating that run. | — | — |

Gaps (opus5-low minus gpt5mini):

| Judge | Gap | Direction |
|---|---|---|
| deepseek-v3.2 | **+17.3pp** | opus5-low ahead |
| gemini-2.5-flash-lite | **+16.0pp** | opus5-low ahead |
| gpt-5-mini (opus arm only, no gpt5mini-arm figure to diff against here) | n/a | opus5-low scores 85.3% on this judge, consistent with the other two |

Split rates (rows where the 3 votes did not agree unanimously; low split = the
judge is internally decisive at temperature 0, not necessarily "correct"):

- `deepseek/deepseek-v3.2`: 1/300 = 0.3%
- `google/gemini-2.5-flash-lite`: 0/300 = 0.0%
- `openai/gpt-5-mini` (150-id opus-arm subset): 3/150 = 2.0%
- `openai/gpt-5-mini` (full 1,409-row corpus, opus arm, for context): 1.7%

Both neutral judges are markedly *more* internally consistent (near-zero split)
than gpt-5-mini is on the same material — but internal consistency and grading
accuracy are different properties, and neither neutral judge has a validated
accuracy figure (see caveat above). A judge that never splits could be decisive
and right, or decisive and *systematically* wrong in a way majority voting cannot
catch — 3 votes smooths provider-side nondeterminism, not a consistent bias.

## Ranking-stability statement

**The ranking (opus5-low ahead of gpt5mini) is stable across every judge family
available for this comparison.** Both third-family neutral judges — deepseek-v3.2
and gemini-2.5-flash-lite, chosen specifically because neither shares a family with
either contestant — put opus5-low ahead by a wide margin (+17.3pp and +16.0pp
respectively) on the identical 150-row stratified subset. gpt-5-mini's own read on
the opus5-low arm (85.3%) sits inside the range the two neutral judges reported for
that same arm (75.3%–87.3%), so nothing here suggests gpt-5-mini's judging is
producing an outlier number for the arm all three judges *can* be compared on.

The one figure this run could not produce — gpt-5-mini's own verdict on its own
answers (the gpt5mini arm), restricted to these 150 ids — was not on disk at
analysis time and was deliberately not regenerated here (a separate full-corpus
run was already producing it; duplicating it would have doubled OpenRouter spend
for a same-family-grading-itself number that carries a known bias risk in this
project already, per `judge_rulesguru.py`'s module docstring). Its absence does
not weaken the ranking-stability claim above, because the claim rests on the two
genuinely third-party reads (deepseek, gemini), both of which independently agree
on direction and are close in magnitude (+17.3pp vs +16.0pp).

**Bottom line: no evidence of a ranking flip across judge families. The margin is
large enough (16–17 points, non-overlapping-ish Wilson CIs) that it is very
unlikely to be a same-family-judging artifact — but per the caveat above, treat
the *exact* accuracy numbers from deepseek and gemini as directional, not
calibrated.**
